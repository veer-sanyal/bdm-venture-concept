## 2. Why this is not a mutation (tuple test)

Per the procedural rule in Part 5 (M0/[C-69]): a proposal that changes none of the five tuple elements , 
customer, asset, document set, mistake, checker, is not a mutation; it is positioning or pricing and
belongs at stage 6. Checked element by element:

- **Customer:** unchanged. Independent ag retailers and custom-applicator businesses under 300 staff,
  exactly as in the ideation file (M5b holds, see section 4).
- **Asset:** unchanged. The ideation file's own asset definition already IS the outcome-linked ledger , 
  "a private ledger of {tank-mix load order ... → the applicable EPA label's ... conditions → eventual
  outcome (state lead-agency misuse finding, drift/crop-injury claim, or none)}." Section 6 of the
  ideation file already conceded the label-check slice is COMPUTED and "by itself supports no
  private-by-operating moat," and named the OBSERVED near-boundary layer as "the only defensible asset
  here", before this screen ran. The screener's lead does not add a new asset; it recommends not
  *marketing* the half of the existing asset that was already flagged as non-differentiated. That is a
  go-to-market decision about which output of the same ledger to surface, not a new asset.
- **Document/state input:** unchanged. The narrower product still needs the load ticket and the label
  (to define "near-boundary" relative to the label's limit) plus the historical outcome record. Same
  three sources as the original tuple.
- **The mistake:** this is where the lead does the most work, and it does not survive scrutiny. The
  original tuple's mistake is "an off-label application." The narrowed pitch, "this mix is technically
  compliant, but historically, mixes this close to the boundary ... have produced downstream drift/injury
  findings X% of the time", is about an *on-label* application, which is a different mistake in kind, not
  degree. But this was already present, not new: the original tuple's outcome-observation section (item 4)
  already listed "a grower/neighbor damage claim" as a distinct outcome type alongside the "state
  lead-agency ... misuse finding," and section 6 already isolated the OBSERVED slice as the part doing the
  real work. The narrowing surfaces an element that was already sitting inside the original tuple; it does
  not introduce one evidence forced into existence.
- **Checker and rule:** this is the actual casualty, and it cuts against the lead, not for it. The
  ideation file is explicit (section 6, citing the STATE.md C-70 correction) that the FIFRA penalty
  "attaches to the recorded use decision itself (label-inconsistent use is citable whether or not physical
  drift actually occurred)." Read the other direction: FIFRA §12(a)(2)(G) and the state statutes the screen
  verified (Iowa §206.19, Montana, South Dakota, Indiana Ind. Code §15-16-4) all penalize use
  "inconsistent with its labeling." A mix the narrowed product concedes is "technically compliant" is, by
  definition, NOT inconsistent with its labeling. **The one checker and one dollar figure this screen
  verified (however downgraded) does not reach the mistake the narrowed formulation proposes to sell
  against.** The narrowed product would need a different checker, plausibly a civil claim from a
  neighboring grower for drift/crop damage, litigated under state tort or nuisance law, not a FIFRA misuse
  citation, and no such instrument, penalty schedule, or settlement figure was verified anywhere in the
  ideation file or the screen. The screen flagged this explicitly and left it open: "ABSORBS: NOT VERIFIED
  / not searched to completion, the plausible candidate (custom-applicator general-liability or 'chemical
  drift' insurance covering third-party crop-damage settlements) was not fetched or confirmed."

Net: four of five tuple elements are unchanged, and the one that shifts (the mistake) drags the checker
out from under the only verified D1 the file has. That is not a mutation escaping a weakness; it is a
narrowing that trades a downgraded-but-real number for an unverified one.
